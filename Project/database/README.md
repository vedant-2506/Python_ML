# RankResume database setup

The application uses PostgreSQL database `rankresume`. Credentials are supplied
through `Backend/.env`; no password or API key is stored in SQL.

## Linux

```bash
sudo -u postgres psql -c "CREATE ROLE root LOGIN PASSWORD 'root';"  # only if the role is absent
sudo -u postgres psql -c "CREATE DATABASE rankresume OWNER root;"   # only if the database is absent
cd /home/vedant-2506/Desktop/Python_ML/Project
PGPASSWORD="$DB_PASSWORD" psql -h localhost -U root -d rankresume -v ON_ERROR_STOP=1 -f database/schema.sql
```

For an existing database, apply only the additive migrations that have not
already been applied:

```bash
PGPASSWORD="$DB_PASSWORD" psql -h localhost -U root -d rankresume \
  -v ON_ERROR_STOP=1 -f Backend/sql/001_backend_tables.sql
PGPASSWORD="$DB_PASSWORD" psql -h localhost -U root -d rankresume \
  -v ON_ERROR_STOP=1 -f Backend/sql/002_shortlisting.sql
```

## Windows PowerShell

```powershell
createdb -U postgres rankresume
psql -U root -d rankresume -v ON_ERROR_STOP=1 -f database/schema.sql
```

Set `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD` in
`Backend/.env` before starting the API. The schema scripts create structure
only. Candidate resumes, company records, jobs, and question-bank data are
not included; restore authorized data separately with `pg_restore` or a
reviewed SQL dump.

`Backend/sql/001_backend_tables.sql` and `Backend/sql/002_shortlisting.sql`
are additive migrations. They do not drop tables, truncate data, or delete
rows. The existing question bank is never regenerated by these migrations.
